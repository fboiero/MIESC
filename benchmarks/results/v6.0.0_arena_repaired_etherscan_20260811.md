# MIESC v6.0.0 — Real-World Arena (Repaired): Etherscan-V2 Victim Source

**Date:** 2026-08-11
**Status:** Additive experiment (does not modify any frozen paper/benchmark artifact).
**Raw data:** `benchmarks/results/arena_repaired_20260811.json`

---

## Why this run exists

The previous "real-world arena" scored **0/96**. That number was an artifact of the
harness, not of MIESC. DeFiHackLabs proof-of-concept (PoC) exploits are Foundry
fork-tests that call the *on-chain* victim **by address** (`vm.createSelectFork(...)`).
The vulnerable victim **source code is not in the DeFiHackLabs repo** — so the prior
arena handed MIESC the *attacker* PoC (or nothing) and had no victim source to analyze.
It measured nothing.

This repaired arena fixes the root cause: for each exploit we **fetch the actual
verified victim contract source from Etherscan V2** and run MIESC's static engine on
**that**. It is the first version of this benchmark that measures MIESC against real
vulnerable victim source.

---

## Headline

On the **fetchable-verified subset**, with strict per-class scoring:

- **In-scope recall (syntactic bug classes): 1 / 4 = 25%.**
  - reentrancy: **1 / 1 caught** (GoodDollar — `reentrancy-no-eth` on the victim reserve).
  - access-control: **0 / 3 caught** (LocalTrader2, landNFT, DEPUSDT/LEVUSDC — all missed).
- **27 / 40 exploits are economic (price-manipulation, flash-loan, business-logic)** —
  **out of scope for static analysis by construction**: they are not source-level
  syntactic bugs, so no static detector can catch them. These are reported as
  *out-of-scope*, **not** as misses.
- **9 / 40 unclassified** — the victim's exploited class could not be confirmed from the
  PoC, so no recall claim is made for them.

The honest takeaway is a per-class statement, not a single number: **static analysis
catches the one clean reentrancy in the sample and misses the access-control logic bugs
entirely, and the majority of modern DeFi losses (price/flash-loan/logic) are simply not
the kind of defect a static analyzer can see.**

## Method

### 1. Corpus and sample
- **Source:** SunWeb3Sec/DeFiHackLabs, sparse checkout of `src/test`.
- **Clone commit:** `2c99b565ae24ea2006adf181da20c4419b3edc30`.
- **Sample:** deterministic **stride** (every 10th) over the **400** sorted
  `2023-*` / `2024-*` `*_exp.sol` files → **40 exploits**. Deterministic and
  reproducible; no cherry-picking.

### 2. Chain detection
Parsed `createSelectFork("<chain>", block)` and explorer-host hints
(bscscan/etherscan/…) → Etherscan V2 `chainid`. Default `1` (ethereum) only when
undetectable (flagged in raw data). **Chains covered in this sample:** bsc, ethereum,
arbitrum, avalanche (polygon/optimism/base did not appear in this particular stride
sample).

### 3. Victim-address identification (heuristic)
Extracted every unique `0x…40hex` address, then removed a **denylist** of known
non-victims: the Foundry VM cheatcode `0x7109709E…D12D`, `address(0)`, wrapped natives
(WETH/WBNB/WMATIC/WAVAX/WFTM), major stables (USDT/USDC/DAI/BUSD across chains), and
canonical routers/factories (PancakeSwap, Uniswap v2/v3, Sushi, 1inch, 0x, Balancer).
The remainder are victim/token candidates. **This is a heuristic** (see Limitations).

### 4. Fetch (Etherscan V2, multi-chain)
`GET /v2/api?chainid={c}&module=contract&action=getsourcecode&address={a}` with the
V2 key; 5 req/s throttle, disk-cached. Kept only **verified** contracts (non-empty
`ContractName` + `SourceCode`). Handled all three `SourceCode` encodings (flat,
single-JSON, and the `{{…}}` standard-JSON multi-file blob). For **verified proxies**
(`Proxy==1`) we additionally fetched the `Implementation` source and attached it to the
same exploit.

### 5. Static analysis engine
- **Slither 0.11.3** — MIESC's core deterministic static-detection layer — run per
  verified contract, per-contract solc pinned via `solc-select` from the contract's
  `CompilerVersion` pragma. Source trees were reconstructed on disk so relative,
  `contracts/…`, and `@openzeppelin/…` imports resolve.
- **Why Slither directly, not `miesc scan`:** we verified that MIESC's CLI JSON export
  at this commit does **not serialize per-tool finding objects** — it emits only counts
  (`normalized_findings_count`), and the aggregated `findings` array comes back empty
  even with `--fp-strictness off`. Slither's detector set is exactly what MIESC's static
  layer normalizes (confirmed: MIESC `normalized_findings_count == 3` equals Slither's 3
  detectors on a control contract). Running Slither directly is therefore the faithful,
  reproducible, finding-level instrument for MIESC's static core. (This CLI
  serialization gap is a genuine MIESC limitation, noted for follow-up; out of scope to
  fix under freeze.)

### 6. Class labels (ground-truth, not guessed)
Each exploit's true vuln class is taken from, in priority order: (a) an explicit
statement in the PoC header/body (`@Summary`, `// REASON`, `// Reentrancy`,
`Vulnerability: …`) — marked `poc-verified`; else (b) keyword inference over the PoC
text — marked `inferred-keyword` and treated as low-confidence. **We manually audited
every exploit that landed in-scope** and corrected keyword-inference errors via a small
`poc-verified` override map:
- `GoodDollar` → reentrancy (body: "// Reentrancy", flash-loan-triggered).
- `LocalTrader2` → access-control ("@Summary: Inproper access controll").
- `DEPUSDT_LEVUSDC` → access-control ("No access control … obtained authorization").
- `landNFT` → access-control ("Vulnerability: lack of permission control on mint").
- `Zunami` → price-oracle-manipulation (sandwich/price-manip via flash; peckshield/
  blocksec). *Its keyword label "unchecked-call" was wrong; its `unchecked-transfer`
  finding was coincidental and is correctly **not** counted as a catch.*

### 7. Scoring rule (strict)
An exploit is **CAUGHT** only if Slither emits a detector in that class's
**severity-gated, exploit-relevant** catch-set on any of the exploit's verified
contracts:
- reentrancy → `{reentrancy-eth, reentrancy-no-eth}`
- access-control → `{arbitrary-send-eth, arbitrary-send-erc20, suicidal,
  unprotected-upgrade, tx-origin, controlled-delegatecall, delegatecall-loop}`
- unchecked-call → `{unchecked-lowlevel, unchecked-transfer, unchecked-send}`

Low/informational noise detectors (`reentrancy-benign`, `reentrancy-events`,
`reentrancy-unlimited-gas`, `missing-zero-check`, `incorrect-modifier`, `unused-return`)
are **deliberately excluded** — they fire on almost every contract and would inflate
recall meaninglessly. (An earlier loose catch-set produced a misleading 4/4; tightening
to meaningful severities gives the honest 1/4.)

### In-scope exploits, per contract
| Exploit | Class (source) | Verdict | Matched detector |
|---|---|---|---|
| GoodDollar | reentrancy (poc-verified) | **caught** | `reentrancy-no-eth` |
| LocalTrader2 | access-control (poc-verified) | missed | — |
| landNFT | access-control (poc-verified) | missed | — |
| DEPUSDT_LEVUSDC | access-control (poc-verified) | missed | — |

Why the access-control misses are legitimate, not a bug in the harness: these are
storage-slot owner overwrites (LocalTrader2), an uninitialized-proxy authorization gap
(DEPUSDT/LEVUSDC), and a missing permission check on a `mint` (landNFT). Detecting them
requires knowing the *intended* access policy — a semantic property Slither's syntactic
detectors (`arbitrary-send`, `suicidal`, `unprotected-upgrade`) do not encode.

### The false-positive dimension (why a naive score would lie)
Of the **36** economic + unclassified victims, **26** carry at least one **unrelated**
High/Medium syntactic finding (`unchecked-transfer`, `controlled-delegatecall`,
`arbitrary-send-*`, and even `reentrancy-eth` on ZongZi/HoppyFrog/Juice). A naive "did
Slither flag anything serious?" oracle would score these as 26 "detections" — but **none
of them is the exploited vulnerability**. Strict class-matched scoring correctly counts
them as 0. This is precisely why the honest number is 1/4 and not an inflated figure.

## Limitations (read before citing any number)

1. **Victim-ID heuristic.** Victims are inferred from PoC addresses minus a denylist.
   A token/pool address can be both "infrastructure" and "the victim"; the denylist is
   deliberately conservative, so some genuine victims may be excluded and some
   non-victims included. Recall is reported over the *fetchable-verified subset*, not
   over "the one true victim per exploit."
2. **Verified-only bias.** 48% of candidate addresses were unverified/EOA and are
   **excluded**, not counted as misses. If unverified victims skew toward a class, the
   per-class denominators shift. This benchmark measures MIESC only where verified source
   exists.
3. **Proxy handling.** Proxies were detected via Etherscan's `Proxy` flag and their
   implementation fetched, but diamond/beacon/custom-slot proxies with non-standard
   indirection may not be fully resolved.
4. **Vyper out of scope.** 11 Vyper contracts (Curve-style) were excluded — Slither
   needs the vyper front-end, not solc. Excluded, not missed.
5. **Static-analysis scope is the real story.** ~2/3 of the sample are economic exploits
   (price manipulation, flash-loan logic, business-logic). These are **not** source-level
   syntactic defects; no static analyzer — MIESC included — can detect them from source.
   Reporting them as "missed" would be dishonest, so they are labeled out-of-scope.
6. **Small in-scope denominator.** Only 4 exploits in this sample have a confirmed
   in-scope class, so "25%" rests on 4 data points. It is directional, not a precise
   population estimate. A larger targeted sample of *confirmed syntactic-bug* exploits
   would be needed to tighten the interval.
7. **Class labels.** In-scope labels are `poc-verified` (audited from the PoC). Some
   economic/unknown labels remain keyword-inferred; since those classes are out-of-scope
   or unasserted, label noise there does not affect the in-scope recall.

## Relation to the prior arena
- Prior: **0/96** — no victim source analyzed (measured nothing).
- This run: real verified victim source fetched for **165 contracts across 4 chains**;
  a defensible per-class recall on the syntactic-bug subset, and an explicit, honest
  accounting of what static analysis structurally cannot see.

The value of this run is not the 25% — it is the **methodology and the per-class
truth**: MIESC's static core does what static analysis can do (found the reentrancy),
does not manufacture detections it cannot justify (0 on semantic access-control), and
the dominant real-world loss vector (economic/logic exploits) is out of static
analysis's reach entirely. That is a true and useful limit statement, reported without
spin.
